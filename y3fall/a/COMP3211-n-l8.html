Planning Identification

2 · CSP 的定义

CSP Problem Definition

  • A special subset of search problems
  • State：由 variables Xi 定义，取值来自 domain Di
  • Goal：找到满足一组给定 constraints 的某个 state
    • Goal test：检查对变量的一组赋值是否满足全部 constraints

4-queens identification problem：

  • variables：棋盘上的各个位置
  • values：Boolean，该位置有没有 queen
  • goal：任意两个 queen 不在同一行、同一列、同一对角线

2.1 例：Map Coloring（澳大利亚）

组成 内容
Variables WA、NT、Q、NSW、V、SA、T
Domains D={red,green,blue}
Constraints 相邻区域颜色不同
— Implicit 写法 WA≠NT
— Explicit 写法 (WA,NT)∈{(red,green),(red,blue),… }（列出所有允许的组合）
Solution 满足所有约束的赋值（不关心路径），例：WA=red、NT=green、Q=red、NSW=green、V=red、SA=blue、T=green

相邻关系（constraint graph 的边）：WA–NT、WA–SA、NT–SA、NT–Q、SA–Q、SA–NSW、SA–V、Q–NSW、NSW–V；T（Tasmania）不和任何区域相邻。

2.2 约束的种类

种类 涉及几个变量 例子
Unary 1 个 SA≠green
Binary 2 个 SA≠WA
High-order 3 个及以上 cryptarithmetic puzzle
  • Binary constraints 可以画成 constraint graph：节点 = 变量，边 = 约束。

组成 内容

3 · 用标准搜索解 CSP

3.1 Standard search formulation

  • State space：每个 state 是已赋的值（partial assignment）
  • Initial state：空赋值 {}
  • Successor function：给一个未赋值的变量赋一个值
  • Goal test：当前赋值完整且满足全部约束

先用最朴素的方法（DFS），再改进。

3.2 Naive DFS 有多大？

设 n 个变量，每个 domain 大小 d：

层 branching factor 这一层节点数
第 1 层 b=nd（任一变量 × 任一值） nd
第 2 层 b=(n−1)d（已经赋了一个） (n−1)d×nd=n(n−1) d2
…
第 n 层 b=d（只剩一个变量） n(n−1)⋯1×dn=n! dn
  • huge search tree；every solution appears at depth n。
  • 但所有可能的完整赋值只有 dn 种——树大了 n! 倍，could we do better?

3.3 Naive DFS 的两个问题

Issue 1：Variable assignments are commutative（赋值顺序无关）

  • [WA = red 然后 NT = green] 和 [NT = green 然后 WA = red] 是同一个结果。
  • → 每个节点只需要考虑给一个固定的变量赋值。
  • branching factor 变成 b=d，树的大小 O(dn)（去掉了 n!）。

Issue 2：每个变量可以赋任何值

  • → 只考虑和之前赋值不冲突的值（不要等到最后才 goal test）。

DFS + 这两个改进 = backtracking search。

4 · Backtracking Search

4.1 Key ideas

  • Idea 1：One variable at a time——赋值可交换，一个节点只对一个变量赋值 → 更小的 branching factor
  • Idea 2：Check constraints as you go——只考虑不和之前赋值冲突的值
  • Idea 3：Backtrack——当某个变量没有合法值可赋时，回到上一个决策点

4.2 地图例子

WA 先试 red / green / blue 三支；在 WA=red 下面 NT 试 green、blue；再往下……某一步发现某个区域没有合法颜色了（No legal values left）→ backtrack。

4.3 算法（课件伪代码）

function BACKTRACKING-SEARCH(csp) returns solution/failure
  return RECURSIVE-BACKTRACKING({}, csp)

function RECURSIVE-BACKTRACKING(assignment, csp) returns soln/failure
  if assignment is complete then return assignment
  var <- SELECT-UNASSIGNED-VARIABLE(VARIABLES[csp], assignment, csp)
  for each value in ORDER-DOMAIN-VALUES(var, assignment, csp) do
    if value is consistent with assignment given CONSTRAINTS[csp] then
      add {var = value} to assignment
      result <- RECURSIVE-BACKTRACKING(assignment, csp)
      if result != failure then return result
      remove {var = value} from assignment
  return failure
代码位置 对应
RECURSIVE-BACKTRACKING({}, csp) initial state：空赋值
SELECT-UNASSIGNED-VARIABLE Idea 1：选一个未赋值变量
if value is consistent … Idea 2：检查和已有赋值的冲突
remove … / return failure Idea 3：这个节点下没有解（某变量没有合法值），回溯

Backtracking = DFS + One variable at a time + Violation-checking

还剩两个问题：先给哪个变量赋值？给它哪个值？ → Heuristics!!

5 · 改进 1：Ordering

5.1 Variable ordering：Minimum Remaining Values（MRV）

  • 选 domain 里剩余合法值最少的变量
  • 课件例子：WA=red、NT=green 之后，SA 只剩 blue（它和 WA、NT 都相邻），Q 还有两种可能 → 先给 SA 赋值（SA=blue）

Why min rather than max?

  • 也叫 「most constrained variable」：它是最容易失败的变量。如果留着不赋，后面它很容易变成「没有值可选」，easily cause backtracking。
  • 先处理它，要么马上成功、要么马上发现失败，失败越早发现，浪费越少（fail-first）。

5.2 Value ordering：Least Constraining Value（LCV）

  • 选定变量之后，选那个让剩下的变量被排除掉的值最少的值
  • 课件例子：WA=red、NT=green，现在给 Q 选值：
    • Q = red：SA 还能选 blue
    • Q = blue：SA（邻接 WA red、NT green、Q blue）一个值都不剩
    • → 选 Q = red

Why least rather than most?

  • 选值是要找到一个解；给其他变量留的选择越多，越不容易走进死路。选「最限制」的值会让剩下的变量 no values left to assign, easily cause backtracking。

注意两者的方向「看起来相反」：变量选最受限的（尽早暴露失败），值选最不限制别人的（尽量保留成功的可能）。

  • Combining these ordering ideas makes 1000-queens feasible.

6 · 改进 2：Filtering

  • Can we detect inevitable failure early?
  • Key idea：为未赋值变量维护 domain，把不可能的选项划掉。

6.1 Forward checking

  • Forward checking：每赋一个值，就把和它冲突的、相邻未赋值变量 domain 里的值划掉。
  • 某个变量的 domain 变空 → No value left, terminate search from this node and backtrack。

课件手推（顺序 WA → Q → V）：

步 WA NT Q NSW V SA
开始 RGB RGB RGB RGB RGB RGB
WA = red R GB RGB RGB RGB GB
Q = green R B G RB RGB B
V = blue R B G R B ∅
  • WA=red：划掉邻居 NT、SA 的 red
  • Q=green：划掉 NT、SA、NSW 的 green
  • V=blue：划掉 NSW、SA 的 blue → SA 空了 → backtrack

6.2 Forward checking 的不足

看 Q=green 那一行：NT = {B}，SA = {B}，而 NT 和 SA 相邻，不能都是 blue！ 这时其实已经注定失败，但 forward checking 没发现——因为它只把信息从已赋值变量传给未赋值变量，不检查未赋值变量之间的约束。

→ Constraint propagation：在未赋值变量之间也继续从约束推到约束。

6.3 Arc consistency

An arc X→Y is consistent if for every x in the tail（X）there is some y in the head（Y）which could be assigned without violating a constraint.

  • 例：WA=red，NT ∈ {blue, green}：
    • WA → NT consistent：WA 的 red，NT 可以选 blue 或 green
    • NT → WA consistent：NT 的 blue / green，WA 的 red 都不冲突
  • 让 X→Y consistent 的做法：把 X 里找不到任何搭档的值删掉（只删 tail 的值）。

课件手推（WA=red、Q=green 之后，未赋值变量 NT、NSW、V、SA；检查它们之间的所有 arc）：

检查的 arc 发生了什么 结果
初始 NT {B}、NSW {R,B}、V {R,G,B}、SA {B}
NSW → SA NSW 取 blue 时，SA 只有 blue，没有搭档 → 删 NSW 的 blue NSW {R}
V → NSW V 取 red 时，NSW 只有 red → 删 V 的 red V {G,B}
SA → NT SA 取 blue 时，NT 只有 blue → 删 SA 的 blue SA = ∅ → Failure
  • 和 forward checking 对比：forward checking 要再赋 V 之后才发现失败；arc consistency 在赋完 Q 之后就发现了。
  • Important：If X loses a value, neighbors of X need to be rechecked!（X 少了值，原本靠这个值做搭档的 Z→X 可能不再 consistent。比如 NSW 删掉 blue 之后，就得重查 V → NSW。）
  • Arc consistency detects failure earlier than forward checking.

7 · Iterative Algorithm（Min-conflicts）

Iterative Improvement for CSPs

  • 用 「complete」states：所有变量都已赋值
  • 用到 CSP 上：
    • 允许 state 有未满足的约束
    • Operators reassign variable values

例：4-queens，移动 queen 来减少 conflicts（互相攻击的对数）：h=5→h=2→h=0。

  • Which variable to pick up? —— 随机选一个有冲突的变量
  • How to choose a new value? —— 选违反约束最少的值（min-conflicts）
  • Iterative min-conflicts is often effective in practice.

和 backtracking 的区别：backtracking 从空赋值一点点建；min-conflicts 从一个完整（可能不合法）的赋值出发修。（下一讲的 local search 就是这个思路。）

8 · Summary

  • CSPs are a special kind of search problem：
    • States are partial assignments
    • Goal test defined by constraints
  • Basic solution：Backtracking search = DFS + one variable at a time + constraint checking
  • Speed-ups：
    • Ordering：variable ordering（MRV）和 value ordering（LCV）heuristically help significantly
    • Filtering：forward checking（从已赋值传到未赋值）；constraint propagation（未赋值之间 → early failure detection）
  • Iterative min-conflicts is often effective in practice

10 · 易错点

  • Naive DFS 的节点数是 n! dn，不是 dn；后者是改进 1 之后的。
  • MRV 是选 remaining values 最少的变量；LCV 是选约束别人最少的值——一个「最多受限」，一个「最少限制」，不要都背成「最少」或「最多」。
  • Arc X→Y consistent 是对 tail X 的每一个值而言；修正时删的是 X 的值，不是 Y 的。
  • Arc consistency 是双向的：X→Y 和 Y→X 是两条不同的 arc，要分别检查。
  • Forward checking 只看「刚赋值的变量 → 它的邻居」，不看未赋值变量之间。
  • T（Tasmania）不和任何区域相邻，任何颜色都行。
  • Min-conflicts 的 state 是完整赋值（允许冲突），backtracking 的 state 是部分赋值（不允许冲突）。
