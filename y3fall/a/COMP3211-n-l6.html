1 · 为什么需要 search（Beyond reflex）

三个应用：

应用 Objective Actions
Route finding shortest? fastest? most scenic? go straight、turn left、turn right
Robot motion planning fastest? most energy efficient? safest? translate and rotate joints
Solving puzzles 用最少步数到达目标配置 move pieces（如 Move12Down）

Beyond reflex 的关键区别：L2–L5 的模型是 reflex-based——输入 x，一次性算出输出。搜索问题要考虑行动的后果（例如 cost），并选出达到目标的最佳行动序列。一步看起来好，不代表整条路线最好。

2 · Search Problem 的定义

Define a search problem

  • A state space（所有可能状态）
  • A successor function
    • Input：当前 state 和一个 action
    • Output：successor state（下一状态）和 cost
  • A start state
  • A goal test：判断一个 state 是不是 goal state

A solution is a sequence of actions（a plan） which transforms the start state to a goal state.

2.1 例 1：Traveling in Romania

组成 内容
State space Cities
Successor function Action：go to an adjacent city；cost = 两城之间的 road distance
Start state Arad
Goal test Is state == Bucharest?
Solution 一串城市，如 Arad → Sibiu → Fagaras → Bucharest

2.2 例 2：8 Puzzles

组成 内容
State space Configurations of tiles（所有摆法）
Successor function Action：move tile left / right / up / down；cost = 1 per move
Start state A configuration of tiles
Goal test Is state == a target configuration?
Solution 一串 tile movements，最后到达 goal state

考题常见形式：给一个新问题（如走迷宫、过河），让你写出这四个组成部分。套路：state 要包含做决定所需的全部信息；successor 写清楚「有哪些 action、到哪个 state、cost 多少」。

3 · General Tree Search

3.1 Search tree

从 Arad 出发，把「从当前城市能去哪」一层层展开成一棵树：

  • 根 Arad；孩子 Sibiu、Timisoara、Zerind
  • Sibiu 的孩子 Arad、Fagaras、Oradea、Rimnicu Vilcea……
  • 注意：树里会重复出现 Arad（Arad → Sibiu → Arad）。树上的一个节点代表的是一条从根出发的路径（a partial plan），不只是一个城市。

3.2 三个 key ideas

  • Frontier：维护「正在考虑、还需要行动」的节点（partial plans）
  • Expansion：从 frontier 里取出一个节点，换成它的孩子节点
  • Exploration strategy：frontier 里先挑哪个节点？——不同搜索算法的唯一区别就在这里

3.3 三类节点

类别 含义
Expanded 已经取出并展开过的
Frontier 已经生成、还没展开的
Unexplored 还没生成的
  • Reached（visited）= expanded ∪ frontier
  • Frontier 把 expanded 区域和 unexplored 区域隔开
  • 展开一个 frontier 节点：
    1. 把它从 frontier 移到 expanded
    2. 把它的孩子从 unexplored 加入 frontier

Important question：Which node to explore first? → 下面四种算法。

4 · Uninformed vs Informed

Definition: Uninformed search strategies Use only the information available in the problem definition.

  • Depth-first search、Iterative deepening search、Breadth-first search、Uniform-cost search

Definition: Informed search strategies Use problem-specific knowledge（e.g., how close a state is to the goal state）to guide the search. Usually more efficient.（下一讲：Greedy、A*）

6 · Depth-First Search（DFS）

Strategy：expand a deepest node first（frontier 当作 stack，后进先出）。

6.1 手推

从 S 开始，一直往最左边走到底，走不通再回退：

S → d → b → a（死路，回退）→ c → a（死路）→ e → h → p → q → q → r → f → c → a → G

Solution：S → d → e → r → f → G（cost = 3+2+2+1+2 = 10，这里碰巧是最便宜的，但 DFS 不保证）

6.2 搜索树的记号

  • b = branching factor（每个节点最多几个孩子）
  • m = maximum depth
  • 第 k 层有 bk 个节点；整棵树节点数
1+b+b2+⋯+bm=O(bm)

6.3 DFS 的四个性质

性质 结论 为什么
Time O(bm) 处理树「左边的一部分」直到深度 m；最坏要把整棵树走完
Space（frontier） O(bm) 最坏情况每一层保留 b 个兄弟节点，共 m 层
Complete? No 如果状态图有环，m 可以是无穷，DFS 会一直往下走
Optimal? No 它找到的是「最左边」的解，不管深度或 cost

为什么 space 只有 bm？ DFS 只沿一条路往下走，frontier 里只存「当前路径上每个节点的未展开兄弟」，每层最多 b 个。

7 · Breadth-First Search（BFS）

Strategy：expand a shallowest node first（frontier 当作 queue，先进先出），一层（tier）一层展开。

7.1 手推

  • Tier 0：S
  • Tier 1：d、e、p
  • Tier 2：b、c、e（d 的孩子）；h、r（e 的孩子）；q（p 的孩子）
  • Tier 3：a、a、h、r、p、q、f
  • Tier 4：……在 S→e→r→f 下面找到 G

BFS 找到的解：S → e → r → f → G（4 步，最浅；但 cost = 9+2+1+2 = 14，比 UCS 找到的 10 贵）。这正说明 BFS 的「optimal」只是步数最少。

7.2 BFS 的四个性质

设 s = 最浅解的深度。

性质 结论 为什么
Time O(bs) 处理最浅解上面的所有节点
Space O(bs) frontier 大约是最后一整层
Complete? Yes 有解的话 s 一定有限
Optimal? Yes（课件写法） 总能找到最浅的解

课件 summary 写 BFS optimal。严格说是「每步 cost 相同时 optimal」（最浅 = 最便宜）。上面的例子里 cost 不相同，BFS 的解（14）就不是最便宜的。答题时写课件结论，必要时加这个条件。

7.3 Quiz：DFS vs BFS

  • When will BFS outperform DFS? —— 解分布得浅时，BFS 更省时间（O(bs) vs O(bm)）。
  • When will DFS outperform BFS? —— DFS 更省内存（O(bm) vs O(bs)）；如果树里解分布得很密（很多解），DFS 随便往下走都容易碰到解，可能比 BFS 好。

8 · Iterative Deepening Search（IDS）

Idea：get DFS's space advantage with BFS's time / shallow-solution advantage.

  • Run a DFS with depth limit 1. If no solution…
  • Run a DFS with depth limit 2. If no solution…
  • Run a DFS with depth limit 3. …

性质：

  • Time O(bs)（s = 最浅解深度）；Space O(bs)
  • Complete、optimal（和 BFS 一样，按深度）
  • Preferred uninformed search algorithm, when the search space is large and the depth of the solution is not known.

为什么重复搜浅层不浪费？ 每多一层，节点数乘 b，最后一层的节点数占了大头；前面各层重复做的那些加起来只是一小部分，所以总时间还是 O(bs)。

9 · Uniform-Cost Search（UCS）

  • g(n) = cost from root to n（从起点到 n 的累计 cost）
  • Strategy：expand lowest g(n)（frontier 是 priority queue，按 g 从小到大）

9.1 手推（考试重点）

每一步：取出 g 最小的节点；把它的孩子按「父的 g + 边 cost」加入 frontier。取出 G 时才结束（不是生成 G 时）。

步 取出（g） 加入 frontier 取出后的 frontier（按 g 排）
1 S（0） d 3、e 9、p 1 p1、d3、e9
2 p（1） q 1+15=16 d3、e9、q16
3 d（3） b 4、c 11、e 5 b4、e5、e9、c11、q16
4 b（4） a 6 e5、a6、e9、c11、q16
5 e（5） h 13、r 7 a6、r7、e9、c11、h13、q16
6 a（6） （无孩子） r7、e9、c11、h13、q16
7 r（7） f 8 f8、e9、c11、h13、q16
8 f（8） c 11、G 10 e9、G10、c11、c11、h13、q16
9 e（9）（S→e 那条） h 17、r 11 G10、c11、c11、r11、h13、q16、h17
10 G（10） —— 结束

Solution：S → d → e → r → f → G，cost 10（和课件一致）。

几个要点：

  • e 出现了两次：经 d 的 g=5，直接从 S 的 g=9。UCS 先展开便宜的那个。
  • 第 8 步生成 G（g=10）时还不能停：frontier 里还有 g=9 的 e，它理论上可能通向更便宜的 G。只有 G 被取出（它是 frontier 里最小的），才能保证没有更便宜的路。
  • 课件里的 Tiers（cost boundary）：UCS 像是按「cost 等高线」一圈圈往外扩，而 BFS 是按「深度」一层层扩。

9.2 UCS 的四个性质

设最优解的 cost 为 C∗，任意两节点之间的最小 cost 为 ε。

性质 结论 为什么
Time O(bC∗/ε) 「effective depth」大约 C∗/ε（每步至少花 ε，到 C∗ 最多走这么多步）
Space O(bC∗/ε) frontier 大约是最后一个 tier 的全部节点
Complete? Yes 有解时 C∗ 有限，且 ε>0
Optimal? Yes 证明见下一讲（A*）

为什么要 ε>0？ 如果有 cost 为 0 的环，UCS 可能在 g 不增加的环上一直转。

10 · Summary

  • Search problem 由 state space、initial state、successor function、goal test 定义
  • Search algorithm 找到达 goal 的 action 序列；Optimal ⇒ minimum-cost
算法 展开谁 Complete Optimal Time Space
DFS 最深的 ✗ ✗ O(bm) O(bm)
BFS 最浅的 ✓ ✓ O(bs) O(bs)
IDS 逐步加深的 DFS ✓ ✓ O(bs) O(bs)
UCS g(n) 最小的 ✓ ✓ O(bC∗/ε) O(bC∗/ε)

（b branching factor，m 最大深度，s 最浅解深度，C∗ 最优解 cost，ε 最小边 cost）

12 · 易错点

  • 树搜索里同一个 state 可以出现多次（不同路径）；节点 = 路径。
  • DFS 的 space 是 O(bm)（乘），time 是 O(bm)（幂），别写反。
  • BFS 的复杂度用 s（最浅解深度），不是 m。
  • UCS 生成 goal 时不能停，要等它被取出。
  • UCS 的 g(n) 是从起点累计的，不是最后一条边的 cost。
  • BFS 只在每步 cost 相同时才真正 cost-optimal；cost 不同时要用 UCS。
  • IDS 的 space 是 O(bs)，不是 O(bs)。
