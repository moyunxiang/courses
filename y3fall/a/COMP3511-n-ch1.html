2 · What Is an Operating System?

2.1 计算机系统的四个组成

组成 说明
Users 人、机器、其他计算机或设备
Application programs 定义如何用系统资源解决问题（编辑器、编译器、浏览器、数据库、游戏…）
Operating system 控制并协调各应用和用户对计算资源的使用
Hardware 基本计算资源：CPU、memory、I/O devices

层次：user → application programs → operating system → computer hardware。

2.2 OS 的作用

  • OS 是一种 system software，是用户 / 应用软件与硬件之间的中介（intermediary）
  • 隐藏硬件的复杂细节，提供简单易用的接口：机器语言层面的结构（尤其 I/O）对程序很复杂；OS 提供抽象层，让程序 / 用户面对的是照片、网页、邮件、文件，而不是设备上的字节和块
  • 高效地分配资源：处理器、内存、计时器、磁盘、鼠标、网卡、打印机……OS 负责有序、受控的分配

2.3 不同环境下的 OS

环境 特点
共享计算机（mainframe、minicomputer） 让所有用户满意：performance vs fairness
个人系统（workstation） 专用资源，重性能而不是公平；可能用服务器上的共享资源
移动设备（smartphone） 资源受限；有各种传感器；特定交互（触屏、语音如 Siri）；为可用性和电池寿命优化
几乎没有用户界面的设备 Embedded systems：OS 预装（在 ROM），如空调、烤面包机、汽车、飞船；Real-time systems 有严格时间约束

2.4 OS 的定义

没有公认的定义。「卖家在你订购 OS 时送来的一切」是个不错的近似，但差别很大。

  • OS is a resource allocator：管理所有资源（硬件和软件）；在冲突的请求之间做出高效而公平的决定
  • OS is a control program：控制程序的执行，防止错误和不当使用
  • 一句话：OS 管理和控制硬件，帮助程序在计算机上运行

（Summary 的说法：OS 的两个目标是 user convenience（方便、安全、受保护、高效地执行程序）和 resource allocation（公平高效地分配资源，硬件如 CPU / 内存，软件如 signal、lock）。）

2.5 常见术语

术语 含义
Kernel 「在计算机上一直运行的那个程序」；本课讲的就是 kernel 的基本功能
Middleware 给应用开发者提供额外服务的软件框架（数据库、多媒体、图形）；在 iOS、Android 中很流行
System programs 随 OS 一起提供、但不属于 kernel（如文字处理、浏览器、编译器）
Application programs 与 OS 无关的程序（如应用商店的 app）

OS = 一直运行的 kernel + middleware frameworks + system programs。

3 · Computer System Organization

3.1 系统组成

  • 一个或多个 CPU core、device controllers，通过共同的 bus 连接，访问共享 memory
  • CPU 和设备并发执行，通过共享 bus 竞争 memory cycles
  • 图（System Architecture with I/O）：processor + cache、memory 通过 bridge/memory controller 接 PCI bus；PCI bus 上挂 graphics controller、IDE disk controller、SCSI controller、expansion bus interface（再接 keyboard、parallel / serial port）

3.2 von Neumann Architecture（往年考过）

执行一条指令的步骤：

  1. Fetch instruction
  2. Decode instruction
  3. Fetch data
  4. Execute instruction
  5. Write back（if any）

组成：

  • CPU：含 ALU（arithmetic logic unit）和 processor registers——PC（Program Counter）、AC（Accumulator）、MAR（Memory Address Register）、MDR（Memory Data Register）
  • Control unit：IR（instruction register）和 PC
  • Memory：存放 data 和 instructions（加上 caches）
  • External mass storage（secondary storage，图中没画）
  • Input、output

核心特征（stored-program architecture）：指令和数据存在同一个内存空间，按地址访问；程序和数据必须先载入内存才能执行。

（Summary 补充：MMU（后面讲）只看到一串内存地址，不知道它们是怎么产生的、是指令还是数据。）

往年考法：选择题问 von Neumann 的核心特征——答「指令和数据存在同一个内存空间、按地址访问」；「指令和数据分开存放」是错误选项（那是 Harvard 结构）。

3.3 Storage 单位

  • bit：0 或 1；byte = 8 bits，大多数计算机上最小的方便操作单位（通常没有移动单个 bit 的指令，但有移动 byte 的）
  • word：该计算机结构的原生数据单位，由一个或多个 byte 组成（64 位寄存器、64 位寻址 ⇒ 64-bit（8-byte）word）
  • KB = 1024 bytes，MB = 10242，GB = 10243，TB = 10244，PB = 10245
  • 厂商常把 MB 说成 100 万字节、GB 说成 10 亿字节
  • 网络例外：用 bits 计（Mb/s、Gb/s），因为网络一次传一个 bit

3.4 Storage Hierarchy

按 speed、cost per unit、capacity、volatility 组织成层次：

层 例子 类别
最上 registers primary，volatile
cache primary，volatile
main memory primary，volatile
nonvolatile memory（SSD 等） secondary，nonvolatile
hard-disk drives secondary
optical disk tertiary
最下 magnetic tapes tertiary

越往上：越快、越小、每字节越贵；越往下：越慢、越大、越便宜。

Characteristics of Various Types of Storage：

Typical size < 1 KB < 16 MB < 64 GB < 1 TB < 10 TB
Implementation custom memory with multiple ports CMOS on-chip or off-chip CMOS SRAM CMOS SRAM flash memory magnetic disk

Backed by cache main memory disk disk disk or tape
  • 层与层之间的移动可以是 explicit（显式，如 OS 把文件从磁盘读进内存）或 implicit（隐式，如硬件管理 cache）
  • 注意 cache 由 hardware 管理，registers 由 compiler 管理

3.5 Main memory

  • CPU 能直接访问的唯一大容量存储
  • Volatile；通常是 DRAM（Dynamic Random-Access Memory）
  • 基本操作是对特定地址的 load 和 store；byte addressable：每个地址对应一个字节
  • 其他形式：开机第一个运行的 bootstrap program 存在 EEPROM（electrically erasable programmable read-only memory）

往年考法：选择题判断 storage hierarchy 的说法——干扰项常把方向说反：registers 比内存慢（错）、main memory nonvolatile（错）、HDD 比内存小（错）；正确的是 main memory is byte addressable。

3.6 Secondary storage

  • main memory 的扩展，提供大容量、非易失的存储，可永久保存大量数据
  • 最常见：HDD 和 NVM（nonvolatile memory，如 SSD）
  • Mechanical：HDD、光盘、全息存储、磁带；Electrical：flash、SSD、FRAM、NRAM（统称 NVM）
  • Mechanical 一般更大、每字节更便宜；electrical 更贵、更小、更可靠、更快
  • （Summary：CPU 间接访问 secondary storage）

3.7 Caching（往年简答题）

  • 重要原则，在计算机的很多层次使用：内存的 cache、地址转换（TLB）、文件块、常用文件名、文件目录、网络路由……
  • Fundamental idea：把一部分信息从较慢但较大的存储临时复制到较快但较小的存储
    • 让常见情况更快，少见情况占比更小
  • 访问时先查 cache：
    • Hit：在 cache 里，直接用（快）
    • Miss：不在，从慢存储复制到 cache 再用
  • cache 通常比被 cache 的存储小得多；cache management：cache size 和 replacement policy
  • 主要指标：cache hit ratio（在 cache 中找到的比例）
Average Access Time=Hit Ratio×Hit Time+Miss Ratio×Miss Time

补充算例：hit ratio 0.9，hit time 1 ns，miss time 100 ns ⇒ 0.9×1+0.1×100=10.9 ns。若 hit ratio 提高到 0.95 但 hit time 变成 5 ns ⇒ 0.95×5+0.05×100=9.75 ns——hit ratio 和 hit time 要一起看。

往年考法（简答）：问 caching 的基本思想，以及「只看 hit ratio 够不够」。 答题要点：基本思想是把较慢较大存储中的一部分信息临时复制到较快较小的存储，让常用数据访问更快。不能只看 hit ratio：hit ratio 是主要指标，但整体性能要用 average access time 衡量，它同时取决于 hit time 和 miss time（miss penalty）。

3.8 为什么 caching 有效：Locality

  • Temporal locality（时间局部性）：最近访问过的项很可能再次被访问
  • Spatial locality（空间局部性）：最近访问项附近（连续块）的项很可能很快被访问（数据和程序都是）
  • 没有访问局部性（例如所有项被等概率访问），cache 根本不会起作用！
  • 做法：保留最近访问的数据靠近处理器（temporal）；把连续块移到上层（spatial）

4 · Multiprocessor and Parallel Systems

4.1 Single-processor systems

  • 过去大多数系统只有一个处理器，含一个单核 CPU
  • core 执行指令、用寄存器存本地数据；能执行通用指令集
  • 还有专用处理器（disk、graphics controller / GPU）：执行有限的特定指令集，通常不执行用户进程的指令

4.2 Multiprocessor systems

  • 现在从手机到服务器都是多处理器
  • N 个处理器的加速比 < N：有额外开销，如共享资源（bus、memory）的竞争
  • 优点：
    • Increased throughput：更多计算能力
    • Economy of scale：共享其他设备（如 I/O）
    • Increased reliability：graceful degradation 或 fault tolerance（一个坏了其他还能工作）
类型 做法
Asymmetric multiprocessing 通常 master-slave：master 给 slave 分配特定任务，master 处理 I/O
Symmetric multiprocessing（SMP） 每个处理器做所有任务，包括 OS 功能和用户进程

SMP 的结构：每个 CPU 有自己的寄存器和私有（local）cache；所有处理器通过 system bus 共享物理内存。

4.3 Multicore

  • 多个 computing core 在同一块物理芯片上
  • 片内通信比片间通信更快
  • 功耗低得多——对手机和笔记本很重要

4.4 NUMA（Non-Uniform Memory Access）

  • 给多处理器加更多 CPU 可能不能扩展：system bus 的竞争成为瓶颈
  • 替代方案：每个 CPU（或一组 CPU）有自己的 local memory，通过小而快的 local bus 访问
  • CPU 之间用共享的 system interconnect 相连，所有 CPU 共享一个物理地址空间
  • 缺点：CPU 访问远端内存（跨 interconnect）时延迟增加——对调度和内存管理有影响（尽量让进程用本地内存）

4.5 术语

术语 含义
CPU 执行指令的硬件
Processor 一块物理芯片，含一个或多个 CPU
Core CPU 的基本计算单元，执行指令并有寄存器存本地数据
Multicore 一块处理器芯片上有多个 core
Multiprocessor system 有多个处理器

5 · Operating System Structure

所有现代 OS 的两个共同特征：

5.1 Multiprogramming（batch system）——为了效率

  • 早期 OS 一次只把一个程序装进内存执行
  • 单个程序不能一直让 CPU 或 I/O 设备都忙（等 I/O 时 CPU 闲着）——所有现代系统都是 multiprogrammed
  • 组织 jobs，让 CPU 总有一个可以执行（一个 job 等 I/O 时，切换到另一个）
  • 大型机中，作业远程提交并排队，通过 job scheduling 选择并装入内存

5.2 Timesharing（multitasking）——为了交互

  • multiprogramming 的逻辑延伸：CPU 在 jobs 之间频繁切换，用户在程序运行时可以和每个 job 交互 ⇒ interactive computing
  • response time 要低于某个阈值
  • 执行中的程序叫 process
  • 多个 process 同时就绪 ⇒ CPU scheduling
  • process 装不进内存 ⇒ swapping（执行中把它们换入换出内存）
  • Virtual memory 允许执行不完全在内存中的 process
Multiprogramming Timesharing
目标 效率（CPU 利用率） 交互（响应时间短）
何时切换 当前 job 等待（如 I/O）时 频繁地（时间片到了也切）

6 · Virtualization 与 Cloud Computing

6.1 Virtualization

  • 把一台计算机的硬件抽象成多个不同的执行环境——制造「每个用户 / 程序都在自己的私有计算机上运行」的错觉
  • 创建 virtual machine（VM），OS 和应用在上面运行
  • 允许一个 OS 作为另一个 OS 里的应用运行（巨大且增长中的产业）

动机：

  • Server consolidation：把多个 OS 整合到更少的硬件平台上，用户可以在跑不同 OS / 不同版本的机器上运行服务
  • 桌面上跑一个 OS（如 Linux、macOS），仍能用另一平台（如 Windows）的原生应用
  • 开发者在一台机器上运行多种 OS 类型和版本——方便测试和调试

组成：

组成 含义
Host 底层硬件系统
VMM（virtual machine manager）/ hypervisor 创建和管理 VM，为 VM / guest OS 提供与 host 相同的接口
Guest OS 得到 host 的虚拟副本的进程，通常是一个 OS

System models（图）：(a) 无虚拟化：processes → kernel → hardware；(b) 虚拟化：每个 VM（VM1、VM2、VM3）各有自己的 kernel 和 processes，跑在 virtual machine manager 之上，VMM 在 hardware 上。

一点历史：

  • 最早用于 IBM mainframe（1972），让多个用户在为单用户设计的系统上并发运行任务
  • VMware 在 Intel x86 CPU 上运行多个 Windows guest，各跑自己的应用
  • VMM 提供与原机器本质相同的环境（接口）；VM 中的程序性能只略有下降（多经过一层软件）；VMM 完全控制系统资源
  • 1990 年代末 Intel CPU 够快 ⇒ 通用 PC 上的虚拟化；Xen、VMware 的技术至今仍在用

6.2 Cloud computing

  • 通过网络把计算、存储、应用作为服务提供
  • 是虚拟化的逻辑延伸：以虚拟化为基础
  • 例：Amazon EC2：数百万服务器、数千万 VM、PB 级存储，按使用付费
类型 含义
Public cloud 通过互联网对任何愿意付费的人开放
Private cloud 公司为自己使用而运营
Hybrid cloud 同时包含 public 和 private 部分
SaaS（Software as a Service） 通过互联网提供一个或多个应用（如文字处理）
PaaS（Platform as a Service） 通过互联网提供可直接用于应用的软件栈（如数据库服务器）
IaaS（Infrastructure as a Service） 通过互联网提供服务器或存储（如备份用的存储）

还有越来越多的其他服务，如 MaaS（Machine learning as a Service）。

8 · 易错点

  • Main memory 是 volatile、byte addressable；是 CPU 唯一能直接访问的大容量存储（CPU 不能直接访问磁盘）。
  • von Neumann：指令和数据在同一个内存里（不是分开）。
  • Cache 性能看 average access time，不能只看 hit ratio。
  • N 个处理器的加速比小于 N。
  • SMP 每个 CPU 有私有 cache，但共享 physical memory。
  • NUMA 共享同一个物理地址空间，只是访问远端更慢。
  • Timesharing 是 multiprogramming 的延伸，目标是交互 / 响应时间。
  • SaaS 给应用，PaaS 给平台（软件栈），IaaS 给基础设施（服务器 / 存储）。
