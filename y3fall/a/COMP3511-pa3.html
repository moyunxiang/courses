Heap layout

block=MetaData⏟9 B: size (8)+status (1)+data⏟size B,next=cur+9+size,walk heap_start→mm_sbrk(0)

mm_malloc(n): first fit

Scan from heap_start and take the first block with status f and size S≥n:

Case Action
S>n+9 split: this block becomes OCCP with size n; a new FREE block of size S−n−9 starts at cur +9+n
n≤S≤n+9 occupy the whole block, no split (the residual block would have ≤0 data bytes)
no block fits mm_sbrk(9 + n), then write a new OCCP block of size n at the old break

Return cur + 9 (the start of the data, not of the meta data).

given1: 1000 free, n=300⇒1000−300−9=691 FREEgiven4: 300 free, n=291⇒300−291=9=meta size⇒no split, OCCP 300

mm_free(p)

Walk the blocks. When cur +9=p, set the status to f and return. Do not merge and do not lower the break.

mm_combine_nearby_free()

For each FREE block, absorb every FREE block directly after it: size +=9+next.size. Repeat until an OCCP block or the break, then move to the next block.

given1: 300+200+9=509,50+314+9=373given3: 509+100+373+2×9=1000given5: 26×1+25×9=251

Pitfalls

  • Return the data pointer. main fills n spaces from it, so returning the meta-data address would overwrite the meta data.
  • The split test is strictly S>n+9. A zero-size block is not allowed.
  • free does not merge blocks; only combine_nearby_free does. After free e in given1, the 50 and 314 blocks stay separate.
  • When merging, recompute the next block from the new size. Absorb a whole run of 3 or more free blocks before moving on (given5).
  • Grow the heap only through mm_sbrk. Never write heap_current_break.
  • The heap is 8000 bytes. Return NULL if mm_sbrk would fail. The official smm does not check this, so the hidden tests should not reach the limit.
