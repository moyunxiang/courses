2. Synchronization

1) Interleaved updates

(a) Possible final values: 10, 13, 15. Either serial order gives 13 (12+3−2).

(b)

Step Statement Result
1 L0 r0 = 12
2 L1 r1 = 12
3 A0 r0 = 15
4 A1 r1 = 10
5 W0 x = 15
6 W1 x = 10

T0's +3 is lost: W1 overwrites x with r1, which was read before W0 stored 15.

2) Atomic instructions and waiting

(a) T0's call returns false, T1's call returns true; lock = true after both.

(b) No. T0 can release and immediately re-acquire the lock (its test_and_set runs before T1's) again and again, so T1 may spin forever; nothing orders the waiters.

3) A semaphore with a waiting queue

(a)

Operation S.value Waiting queue
P0 wait(S) 0 empty
P1 wait(S) −1 P1
P2 wait(S) −2 P1, P2
P0 signal(S) −1 P2 (P1 made ready)

(b) A negative value −k means k processes are blocked on S; ∣S.value∣ = length of the waiting queue.

3. Classic Synchronization Problems

1) A bounded job buffer

(a) mutex = 1, empty = 8 − 3 = 5, full = 3

(b)

Blank Call Purpose
B1 wait(empty) reserve a free slot (block if buffer full)
B2 wait(mutex) exclusive access for insert
B3 signal(mutex) release buffer after remove
B4 signal(empty) one more free slot

(c) Buffer full: empty = 0, full = 8, mutex = 1.

  1. Producer: wait(mutex) succeeds (mutex = 0).
  2. Producer: wait(empty) blocks (empty = 0) while holding mutex.
  3. Consumer: wait(full) succeeds (full = 7).
  4. Consumer: wait(mutex) blocks (mutex = 0).

Deadlock: producer waits for empty (only the consumer can signal it), consumer waits for mutex (held by the producer). Fix: producer calls wait(empty) before wait(mutex).

2) Readers and writers

(a) R1 is blocked on rw_mutex (while holding mutex); R2 is blocked on mutex; read_count = 1.

(b) The second (last) departure: it makes read_count = 0, so it calls signal(rw_mutex). read_count++/-- is a non-atomic read-modify-write; without mutex an update can be lost → rw_mutex released while readers remain, or never released.

(c) Yes. rw_mutex is released only when read_count = 0; new readers skip wait(rw_mutex) (read_count ≠ 1) and increment read_count, so with overlapping arrivals read_count never reaches 0 and the writer waits forever.
