1 · 从确定性到不确定性

  • So far: search problems：确定性的。state s 做 action a，一定到 s′=Succ(s,a)。
  • Uncertainty in the real world：同一个 (s,a) 可能到达不同的 s1′、s2′……

1.1 例：Volcano Crossing

网格上从 Start 出发，越过火山（-50），想到达 Terminal（+20，fabulous view）：
-50 0 -50 20 ← Terminal
Start 0 -50 0
0 0 0
  • 用确定性搜索（UCS，按 path reward 探索）：能找到一条到 terminal 的路。
  • 现实中：每个 action 都有可能打滑（slipping），可能到达别的格子（比如掉进火山）。
  • → Need algorithms to handle non-deterministic world!

2 · Markov Decision Process 的定义

Definition: Markov decision process

  • States：状态集合
  • sstart∈States：起始状态
  • Actions(s)：在状态 s 可做的动作
  • T(s,a,s′)：transition probability，在 s 做 a 后到达 s′ 的概率
  • Reward(s,a,s′)：这次转移 (s,a,s′) 得到的 reward
  • IsEnd(s)：s 是否是 terminal state

和 search problem 的主要区别：

Search problem MDP
Successor function Succ(s,a)（确定的一个 s′） T(s,a,s′)（s′ 的概率分布）
Cost function Cost(s,a)（越小越好） Reward(s,a,s′)（越大越好）

3 · 例：Dice Game（贯穿全讲）

Example: Dice game，每一轮 r=1,2,…：

  • 你选 stay 或 quit
  • quit：得 $10，游戏结束
  • stay：得 $4，然后掷 6 面骰：
    • 掷出 1 或 2 → 游戏结束（概率 1/3）
    • 否则 → 进入下一轮（概率 2/3）

Question：选 stay 时，结束和继续的概率？——结束 2/6=1/3，继续 4/6=2/3。

3.1 画成图

  • 状态：in（游戏中）、end
  • 中间的虚线圈 (in, stay)、(in, quit) 是 chance node（做完决定、等随机结果的状态）
  • in --stay--> (in, stay)：以 2/3 回到 in 得 $4，以 1/3 到 end 得 $4
  • in --quit--> (in, quit)：以 1 到 end 得 $10

3.2 Transition probabilities

Definition：T(s,a,s′) 指定在状态 s 做动作 a 后到达 s′ 的概率。

s a s′ T(s,a,s′)
in quit end 1
in stay in 2/3
in stay end 1/3

对每个 s 和 a：∑s′∈StatesT(s,a,s′)=1（概率分布要归一）。

3.3 Rewards、utility

一直 stay，可能产生的 paths：

Path 总 reward
[in; stay, 4, end] 4
[in; stay, 4, in; stay, 4, end] 4 + 4 = 8
[in; stay, 4, in; stay, 4, in; stay, 4, end] 12
[… 四次 …] 16
… …

每条 path 的总 reward 叫 utility。 它是一个随机变量（取决于骰子）。

这些 path 的概率怎么算？ 第 k 轮才结束 = 前 k−1 轮都继续、第 k 轮结束：

P(utility=4k)=(23)k−1⋅13

所以 4、8、12、16 的概率依次是 13≈0.33、29≈0.22、427≈0.15、881≈0.10（课件的柱状图）。

3.4 Expected utility（value）

13(4)+23⋅13(8)+23⋅23⋅13(12)+⋯=12

为什么是 12？ 平均玩几轮：每轮以 1/3 结束，期望轮数 =1/(1/3)=3；每轮 $4，所以 3×4=12。

对比：quit 直接拿 10 < 12，所以一直 stay 更好。

4 · Discounting

Definition: utility with discount Path：s0,a1r1s1,a2r2s2,…（action、reward、new state）

u1=r1+γr2+γ2r3+γ3r4+⋯(0≤γ≤1)

  • 调整未来 reward 的重要性：越往后乘的 γ 次方越高，指数衰减。

课件例子（path [stay, stay, stay, stay]，每步得 4）：

Discount 含义 计算
γ=1 save for the future（未来和现在一样重要） 4+4+4+4=16
γ=0 live in the moment（只看眼前） 4+0⋅(4+⋯ )=4
γ=0.5 balanced life 4+12⋅4+14⋅4+18⋅4=7.5

5 · Solution 是什么：Policy

  • Search problem 的解：path（一串 actions）
  • MDP 的解：policy

Definition: policy A policy π is a mapping from each state s∈States to an action a∈Actions(s).

为什么不能给一条 path？ 结果是随机的，你事先不知道会到达哪个 state；所以要为每个可能到达的 state 都规定好怎么做。

例（volcano crossing）：π(1,1)=S、π(2,1)=E、π(3,1)=N……

6 · Policy Evaluation

6.1 怎么评价一个 policy？

Definition: utility

  • 从一个 state 出发、遵循一个 policy，会产生很多可能的随机 paths。
  • 一条 path 的 utility = path 上 reward 的（discounted）和——是一个随机变量。

→ 用 expected utility（也叫 value，越高越好）评价 policy。

Definition: Value of a policy Vπ(s) = 从状态 s 出发、遵循 policy π 得到的 expected utility。

Definition: Q-value of a policy Qπ(s,a) = 在状态 s 先做 action a，之后遵循 π，得到的 expected utility。

区别：Vπ(s) 是「站在 state 上」；Qπ(s,a) 是「站在 chance node (s,a) 上」——第一步的 action 由你指定，不一定是 π(s)。

6.2 V 和 Q 的关系（核心公式）

Vπ(s)={0if IsEnd(s)Qπ(s,π(s))otherwise
  • terminal state：没有后续 action，没有更多 reward
  • 否则：action 由 π 给出，value 就等于做 π(s) 的 Q-value
Qπ(s,a)=∑s′T(s,a,s′)[Reward(s,a,s′)+γVπ(s′)]
部分 含义
T(s,a,s′) transition probability（对所有可能的 s′ 加权平均）
Reward(s,a,s′) immediate reward
γVπ(s′) 到 s′ 之后的 discounted value（future rewards）

直觉：做了 a 之后，按概率到每个 s′；每种情况下得到「这一步的 reward + 之后打折的价值」，再按概率求平均。

6.3 Dice game：解方程

令 π = 「stay」policy，π(in)=stay，γ=1：

Vπ(end)=0Vπ(in)=13(4+Vπ(end))+23(4+Vπ(in))

两个变量、两个线性方程。代入 Vπ(end)=0：

V=43+83+23V=4+23V  ⇒  13V=4  ⇒  Vπ(in)=12

Closed form solution：Vπ(end)=0，Vπ(in)=12（和 3.4 的级数结果一致）。

But, what if we have 100,000 states? 解线性方程组要对 100,000×100,000 的矩阵求逆，非常贵。

6.4 Iterative algorithm

Key idea：从任意的 value 开始，反复套用递推式，收敛到真实值。

Algorithm: policy evaluation

Initialize Vπ(0)(s)←0 for all states s.

For iteration t=1,…,tPE:

  • For each state s:
    Vπ(t)(s)←∑s′T(s,π(s),s′)⋅[Reward(s,π(s),s′)+γVπ(t−1)(s′)]

右边就是 Q(t−1)(s,π(s))。

  • 迭代多少次（tPE）？ 直到 value 基本不变：
max⁡s∈States∣Vπ(t)(s)−Vπ(t−1)(s)∣≤ϵ
  • 不需要存每一轮的 Vπ(t)，只要最近两轮 Vπ(t) 和 Vπ(t−1)。

MDP complexity：S 个 states，每个 state A 个 actions，S′ 个 successors（T(s,a,s′)>0 的 s′ 数）

Policy evaluation 的 Time：O(tPE SS′)

（每轮对 S 个 state 各算一次，每次对 S′ 个 successor 求和；policy 固定，所以没有 A。）

6.5 Dice game 上的迭代（表格：end、in）

递推：

V(t)(in)=13(4+0)+23(4+V(t−1)(in))=4+23V(t−1)(in)
t V(end) V(in) 计算
0 0.00 0.00 初始化
1 0.00 4.00 4+23⋅0
2 0.00 6.67 4+23⋅4
3 0.00 8.44 4+23⋅6.67
100 0.00 12.00 收敛

7 · Optimal Value 与 Value Iteration

7.1 我们真正要的是 optimal policy

怎么得到？ 朴素办法：枚举所有 policy，各自做 policy evaluation，取最好的。

Issue：policy 的数量是 state 数的指数级（准确说是 AS：每个 state 有 A 种选择）——复杂度太高！

7.2 Optimal value

Goal：直接估计最大的 expected utility。

Definition: optimal value The optimal value Vopt(s) is the maximum value attained by any policy.

和 policy evaluation 非常像，只有一处不同：不再用固定 policy 给的 action，而是取让 Qopt(s,a) 最大的 action。

Vopt(s)={0if IsEnd(s)max⁡a∈Actions(s)Qopt(s,a)otherwise
Qopt(s,a)=∑s′T(s,a,s′)⋅[Reward(s,a,s′)+γVopt(s′)]

7.3 Value iteration 算法

Algorithm: value iteration [Bellman, 1957]

Initialize Vopt(0)(s)←0 for all states s.

For iteration t=1,…,tVI:

  • For each state s:
    Vopt(t)(s)←max⁡a∈Actions(s)∑s′T(s,a,s′)⋅[Reward(s,a,s′)+γVopt(t−1)(s′)]

max 后面那一项就是 Qopt(t−1)(s,a)。

Time：O(tVI SAS′)——比 policy evaluation 多一个 A，因为每个 state 都要遍历所有 action 找最大的 Q-value。

7.4 Extract optimal policy

有了 Qopt，直接读出最优 policy：

πopt(s)=arg⁡max⁡a∈Actions(s)Qopt(s,a)

即在每个 state 选让 optimal Q-value 最大的 action。

补充：dice game 的 value iteration（γ=1）：Vopt(in)=max⁡{10⏟quit,  4+23Vopt(in)⏟stay}。收敛到 Vopt(in)=12，此时 Qopt(in,stay)=12>Qopt(in,quit)=10，所以 πopt(in)=stay。

8 · Value Iteration 例：Car Racing（手算重点）

  • 机器人赛车想跑得远、跑得快
  • Three states：Cool、Warm、Overheated（terminal）
  • Two actions：Slow、Fast
  • Going faster gets double reward
  • Assume no discount（γ=1）
s a s′ T Reward
Cool Slow Cool 1.0 +1
Cool Fast Cool 0.5 +2
Cool Fast Warm 0.5 +2
Warm Slow Cool 0.5 +1
Warm Slow Warm 0.5 +1
Warm Fast Overheated 1.0 −10

Iteration 0：全部初始化为 0，V0=[0,0,0]（Cool、Warm、Overheated）。

Iteration 1（用 V0）：

  • Cool：
    • slow：1×[1+0]=1
    • fast：0.5×[2+0]+0.5×[2+0]=2
    • 取 max → V1(Cool)=2
  • Warm：
    • slow：0.5×[1+0]+0.5×[1+0]=1
    • fast：1×[−10+0]=−10
    • 取 max → V1(Warm)=1
  • Overheated：terminal state → V1=0
V1=[2,  1,  0]

补充：Iteration 2（课件只算到 V1；用 V1 继续）：

  • Cool：
    • slow：1×[1+2]=3
    • fast：0.5×[2+2]+0.5×[2+1]=3.5
    • → V2(Cool)=3.5（fast）
  • Warm：
    • slow：0.5×[1+2]+0.5×[1+1]=2.5
    • fast：1×[−10+0]=−10
    • → V2(Warm)=2.5（slow）
  • Overheated：0
V2=[3.5,  2.5,  0]

解题套路：每个 state × 每个 action，写出「∑ 概率 × [reward + 上一轮的 V(s′)]」，取 max；terminal 恒为 0；一律用上一轮的 V，不要用本轮刚算出来的。

9 · Summary

  • MDPs：应对不确定性的模型
  • Solutions：policies rather than paths
  • Policy evaluation：(MDP,π)→Vπ
  • Value iteration：MDP→(Vopt,Qopt,πopt)
Policy evaluation Value iteration
输入 MDP + 固定的 π MDP
输出 Vπ Vopt、Qopt、πopt
更新 用 π(s) 这一个 action 对所有 action 取 max
Time O(tPE SS′) O(tVI SAS′)

11 · 易错点

  • Reward 写成 Reward(s,a,s′)，依赖到达的 s′；求和时 reward 在方括号里面，要乘上概率。
  • γ 只乘在未来的 value V(s′) 上，不乘在 immediate reward 上。
  • Terminal state 的 value 恒为 0，迭代时不要更新它。
  • Policy evaluation 用 π(s) 一个 action，没有 max；value iteration 才有 max。
  • 复杂度：policy evaluation 没有 A，value iteration 有 A。
  • 迭代时右边一律用上一轮的 V(t−1)。
  • Policy 的个数是 AS，不是 SA。
