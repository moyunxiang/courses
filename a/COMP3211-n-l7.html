0 · 这一讲在讲什么

Roadmap：Greedy Search → A* Search → Inventing Heuristics

必考：Greedy 为什么不 complete、不 optimal（课件 Lasi → Fagaras 的环）；A* 的 f=g+h；admissible 的定义；课件「Is A* optimal?」反例；A* 最优性证明三步；8 puzzle 两个 heuristic 的值（8、18）以及为什么 admissible；dominance 和 max of heuristics。

1 · 回顾与动机

算法 先展开谁
DFS deepest node
BFS shallowest node
UCS lowest path cost g(n)

它们的 strategy 只用了问题定义里的信息（uninformed）——不知道目标在哪个方向，只能「四面八方」地搜。

Informed search：

  • 用 problem-specific（heuristic）knowledge 决定先展开哪个节点
  • guide search towards the goal instead of all over the state space

2 · Greedy Search

2.1 Key ideas

  • 展开 frontier 中看起来离 goal 最近的节点
  • 需要一个 evaluation function h(n)：估计从节点 n 到 goal 的 cost
  • 选 frontier 中 h 最小的节点

h(n) 怎么来？ 用问题本身的知识。Romania 例子：

h(n)=straight-line distance from n to Bucharest
  • useful but potentially error-prone（所以叫 heuristic）
  • heuristic functions are problem-specific

2.2 Romania 上的 Greedy 手推

步 展开 生成的孩子（h） 下一步选
1 Arad（366） Sibiu 253、Timisoara 329、Zerind 374 Sibiu（253 最小）
2 Sibiu Arad 366、Fagaras 178、Oradea 380、Rimnicu Vilcea 193 Fagaras（178）
3 Fagaras Sibiu 253、Bucharest 0 Bucharest（0）→ 到达

Greedy 的路径：Arad → Sibiu → Fagaras → Bucharest，路程 140+99+211=450。

补充（用课件地图上的距离）：经 Rimnicu Vilcea、Pitesti 的路是 140+80+97+101=418，更短。Greedy 只看「离终点还有多远」，不看「已经走了多远」，所以不 optimal。

2.3 Greedy Search: Complete?（课件反例）

Task：从 Lasi 到 Fagaras，h(n) = 到 Fagaras 的直线距离。

  • Lasi（h=90）的邻居：Neamt（h=80）、Vaslui（h=100）
  • 选 h 小的 Neamt → Neamt 是死胡同，唯一邻居是 Lasi（h=90）
  • frontier 里 Lasi（90）比 Vaslui（100）小 → 又回到 Lasi → 又选 Neamt → ……

Complete? No! In a cycle! 真正的路要经过 Vaslui，但它的 h 一直比 Lasi、Neamt 大，永远轮不到。

Any idea to jump out of the cycle? → 像 UCS 一样把已走的 path cost 也算进去：

节点 g h g+h
Lasi（根） 0 90 90
Neamt 87 80 167
Vaslui 92 100 192
Lasi（经 Neamt 回来） 87+87=174 90 264

展开 Neamt 后，回到 Lasi 的 g+h=264>192，所以下一个展开的是 Vaslui，跳出了环。这就是 A*。

3 · A* Search

3.1 Key ideas

  • 展开 frontier 中 g(n)+h∗(n) 最小的节点
    • g(n)：从根到 n 的 cost
    • h∗(n)：从 n 到 goal 的最优（真实） cost
  • 我们很少知道 h∗(n)，但可以有 heuristic 近似 h(n)
  • A* = tree search，frontier 的优先级由
f(n)=g(n)+h(n)

Combining UCS and Greedy Search：

部分 含义
g(n) backward cost：已经花了多少（UCS）
h(n) forward cost：估计还要花多少（Greedy）
g(n)→0 退化成 greedy search
h(n)→0 退化成 uniform-cost search

直觉：f(n) 是「经过 n 的完整路线总 cost 的估计」。A* 每次展开估计总 cost 最小的那条路。

3.2 Is A* Optimal?（课件反例）

图：S → A cost 1，A → G cost 3，S → G cost 5。h(S)=7，h(A)=6，h(G)=0。

节点 g h f
S 0 7 7
A 1 6 7
G（直接从 S） 5 0 5
  • 展开 S 后，frontier 里 G 的 f=5<7，先取出 G → 返回 S → G。
  • Do we find a solution path? Yes, S → G.
  • Is it optimal? No! S → A → G 的总 cost 是 1+3=4<5。

What went wrong?

  • h(A)=6，但 A 到 G 实际只要 3——heuristic 高估了。
  • 于是「实际很差的 goal 的 cost（5）< 好路线的估计 cost（7）」，好路线被压在后面。
  • → 需要 heuristic 不能高估真实 cost。

补充验证：若把 h(A) 改成不高估的值，例如 h(A)=2，则 f(A)=3<5，先展开 A，生成 G（经 A）f=4<5，取出的就是 cost 4 的最优路。

3.3 Admissible heuristics

Definition：A heuristic h is admissible（optimistic） if for any node n:

0≤h(n)≤h∗(n)
where h∗(n) is the true cost from node n to the goal.

  • h(n)≤h∗(n)：never overestimate the actual cost from n to the goal
  • 例子：
    • Route finding：直线距离永远 ≤ 实际公路距离（两点之间直线最短）
    • Food finding（迷宫吃豆）：Manhattan distance 永远 ≤ 迷宫里的实际距离（墙只会让路变长）
  • Remember：A* 用 f=g+h；If h is admissible, A* search is optimal.

3.4 Optimality of A* Tree Search（证明，考试可能要写）

Assume：A 是 optimal goal node，B 是 suboptimal goal node，h admissible。 Claim：A 会在 B 之前被展开（所以 A* 返回的是 A）。

Proof：设 B 在 frontier 上。A 的某个祖先 n 也在 frontier 上（可能就是 A 自己）。证明 n 在 B 之前展开：

1. f(n)≤f(A)

f(n)=g(n)+h(n)definition of f≤g(n)+h∗(n)admissibility of h=g(A)n 在 A 的最优路径上=f(A)h=0 at a goal

（g(n)+h∗(n) 就是「从根经 n 到 A 的真实 cost」，即 g(A)。）

2. f(A)<f(B)

  • g(A)<g(B)：B 是 suboptimal
  • 在 goal 处 h=0，所以 f(A)=g(A)<g(B)=f(B)

3. n is expanded before B

  • f(n)≤f(A)<f(B)，A* 按 f 从小到大取，所以 n 先于 B
  • 对 A 的每个祖先都成立 → all ancestors of A are expanded before B
  • → A is expanded before B → A* tree search is optimal ∎

3.5 UCS vs A*

课件两张搜索树的图：

  • UCS：以起点为中心、向所有方向均匀扩张（cost 等高线是圆）
  • A*：扩张区域朝 goal 方向拉长，展开的节点少得多

3.6 Properties of A*

性质 结论
Optimal? Yes, if the heuristic is admissible
Complete? Yes
Time Exponential in the length of the solution
Space Exponential in the length of the solution

With a good heuristic, significant savings are possible compared to uninformed search.

4 · Inventing Heuristics

4.1 Relaxed problems

  • Admissible heuristics 常常是 relaxed problem（放宽限制、允许新 action 的问题）的精确解的 cost。
  • The cost of an exact solution to a relaxed problem is a good heuristic for the original problem.

为什么 relaxed problem 的解一定 admissible？ 放宽限制只会让可选的路变多；原问题的任何解在 relaxed problem 里也是解，所以 relaxed 的最优 cost ≤ 原问题的最优 cost，即不会高估。

4.2 8 Puzzle：两个 heuristic

Start 和 Goal（空格记作 ␣）：

Start Goal
7 2 4 ␣ 1 2
5 ␣ 6 3 4 5
8 3 1 6 7 8

Heuristic 1：Number of tiles misplaced

  • 数一数有多少块不在目标位置（空格不算）：8 块全错 → h(start)=8
  • 为什么 admissible？ 每块错位的 tile 至少要移动一次，一次只能移动一块 → 至少 8 步。
  • 对应的 relaxed problem：tile 可以直接瞬移到任何位置。

Heuristic 2：Total Manhattan distance

  • 每块 tile 当前位置到目标位置的「横向 + 纵向」格数之和：
tile 7 2 4 5 6 8 3 1
距离 3 1 2 2 3 2 2 3

h(start)=3+1+2+2+3+2+2+3=18

  • 为什么 admissible？ 每次移动只让一块 tile 走一格，每块至少要走它的 Manhattan 距离那么多步。
  • 对应的 relaxed problem：tile 可以移到相邻格，不管那里有没有别的 tile。

Statistics（Andrew Moore）：最优路径分别为 4、8、12 步时，平均展开的节点数：

4 steps 8 steps 12 steps
UCS 112 6,300 3.6×106
A* TILES 13 39 227
A* MANHATTAN 12 25 73

→ A better approximation h(n) of the actual cost h∗(n) results in a faster search.

4.3 Heuristic Dominance

Dominance：h1≥h2 if ∀n:  h1(n)≥h2(n)

  • Roughly speaking, larger is better as long as both are admissible.（越接近 h∗ 越好，但不能超过）
  • The zero heuristic is pretty bad：h=0 时 A* 就是 UCS。
  • The exact heuristic（h=h∗）is pretty good, but usually too expensive to compute。
  • 8 puzzle：Manhattan ≥ misplaced tiles（每块错位的 tile Manhattan 距离至少为 1），所以 Manhattan dominates。

为什么大的好？ h 越接近真实 cost，f 就越准，A* 越不会去展开那些实际上不在最优路上的节点。

4.4 Combining multiple heuristics

Question：有 h1,…,hm，谁也不 dominate 谁，怎么办？

h(n)=max⁡(h1(n),…,hm(n))

Max of admissible heuristics is admissible and dominates all the individual heuristics!

  • admissible：每个 hi(n)≤h∗(n)，最大的那个也 ≤h∗(n)
  • dominates：max 在每个 n 上都 ≥ 每一个 hi(n)

（注意是 max，不是 sum——加起来可能高估。）

5 · Summary

  • Heuristic functions 估计节点到 goal 的 cost（forward cost）
  • Good heuristics can dramatically reduce search
  • Greedy search 展开 h 最小的节点——neither complete nor optimal
  • A* search 展开 f=g+h 最小的节点（backward + forward cost）
  • Admissible heuristics can be derived from exact solution of relaxed problems
算法 优先级 Complete Optimal
UCS g(n) ✓ ✓
Greedy h(n) ✗ ✗
A* g(n)+h(n) ✓ ✓（h admissible 时）

7 · 易错点

  • Greedy 用的是 h，A* 用的是 g+h，UCS 用的是 g——三者别混。
  • Admissible 是「不高估」：h≤h∗。高估才会破坏最优性；低估只会让搜索变慢。
  • 课件反例里出错的是 h(A)=6>h∗(A)=3，不是 h(S)。
  • A* 也要等 goal 被取出时才停，生成时不能停（否则证明不成立）。
  • Manhattan distance 是对每块 tile分别算再求和，空格不算。
  • 组合 heuristics 用 max，不要用 sum 或 average。
  • Dominance 是对所有 n 成立的不等式，只在 start 处大不够。
