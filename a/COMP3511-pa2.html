Only mlfq() and a few helpers are needed; parsing and printing are given. The full source is kept offline, not on this page, because JPlag is run on every submission. Tested on csl2wk01 (gcc 11.5, gcc -std=c99 -Wall, no warnings): 8/8 given cases pass, and 300 random inputs give output identical to the official mlfq executable.

Rules (from the lab 5 step-by-step example)

Event Action
Arrival at time t append to the end of Q0
Each time unit run the head of the highest non-empty queue for 1 unit
Finished remove from the MLFQ
Used tqi in total at level i move to the end of Qi+1, reset its used time
Pre-empted by a higher queue stays at the head of its queue, keeps its used time
Last queue FCFS (tq=1000)

Gantt chart: consecutive units of the same process are merged into one item, even across a demotion. For example, in in05, J runs 18→28 as a single item.

Simulation loop (1 time unit per step)

Repeat while some process is unfinished:

  1. Append every process with arrival=t to the end of Q0.
  2. Let i be the highest non-empty level and p=head(Qi).
  3. Add one unit of p to the chart (merge with the last item if it is also p). Then remainp–, usedp++, t++.
  4. If remainp=0: dequeue p and count it as finished.
  5. Else if usedp=tqi: dequeue p, enqueue it into Qmin⁡(i+1, N−1), and set usedp=0.

Data structures (no extra headers): int queue[4][10] plus queue_size[4] (index 0 = head, dequeue shifts left), and used_quantum[10]. Set remain_time = burst_time before the loop.

Arrivals are added before choosing the process at time t. This order is what makes the new arrival pre-empt (P3 at t=4 and P4 at t=6 in in01). A demoted process is appended after the processes already waiting in that queue (P4 joins Q1 behind P1 at t=8).

Pitfalls

  • Do not restart the quantum after pre-emption. At t=8, P1 has only 4−2=2 units left at level 1, so it runs 8→10, not 8→11.
  • Do not move a pre-empted process to the tail of its queue.
  • Do not create a new chart item when the same process continues after a demotion.
  • The skeleton file uses CRLF line endings. Converting to LF is harmless for gcc.
