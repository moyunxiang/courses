1 · Motivation

  • 很多应用是多线程的：
    • 浏览器：一个线程显示图片 / 文字，另一个从网络取数据
    • 文字处理：一个线程显示图形，一个响应键盘，第三个在后台做拼写和语法检查
  • 大多数 OS kernel 是多线程的：如 Linux 启动时创建若干 kernel threads，各做特定任务（管理设备、内存管理、中断处理）
  • 能利用多核的处理能力：数据挖掘、图形、AI 等广泛使用并行编程
  • 进程创建耗时耗资源：process creation 是 heavy-weight，thread creation 是 light-weight——同一进程的线程共享 code、data 等

多线程程序的例子：嵌入式系统（电梯、飞机、医疗系统、手表：单个程序、并发操作）；现代 OS kernel（内部并发处理多用户请求，kernel 内部不需要保护）；数据库服务器（多用户并发访问共享数据 + 后台处理）；网络服务器（文件、Web、订票系统）；并行编程（把程序和数据拆到多个线程）。

2 · Thread 是什么

A thread is a basic unit of CPU utilization——独立调度和运行（an instance of execution），由 thread ID、program counter（PC）、register set、stack 表示。它和同一进程的其他线程共享 code、data 和其他 OS 资源（如 open files、signals）。

Single vs multithreaded process（课件图）：

单线程进程 多线程进程
共享 code、data、files code、data、files（所有线程共享一份）
每个线程 registers、PC、stack 每个线程各一份 registers、stack、PC

2.1 四个好处（必背）

好处 说明
Responsiveness 进程的一部分（一个线程）被阻塞时，其他部分可以继续执行——对有 UI 的交互应用尤其重要
Resource Sharing 线程默认共享进程的资源，比进程之间的 shared memory 或 message passing 容易——它们本来就在同一地址空间
Economy 创建线程比创建进程便宜得多（时间和内存）；同一进程的线程间 context switch 通常比进程间快
Scalability 进程能利用多核架构

往年考法：关于多线程进程正确的是「thread creation 通常比 process creation 快」。错误选项：「每个线程有自己的地址空间和 file descriptors」（共享）、「同一进程的线程不能在多核上并发运行」（能）、「不能利用多核」（能）。

3 · Multicore Programming

多线程编程让多核的使用更高效、提高并发性。

3.1 五个挑战

挑战 含义
Dividing tasks 怎样拆成独立的、可并发的任务
Balance 每个任务做「相等」的工作量
Data splitting 任务用到的数据要拆开，在不同核上运行
Data dependency 有数据依赖就要同步
Testing and debugging 执行路径各不相同，调试困难

3.2 Concurrency vs Parallelism（往年选择题）

  • Parallelism：系统能同时执行多于一个任务
  • Concurrency：支持多于一个任务都在推进（making progress）——可以是单核上按时间复用，由 scheduler 提供 concurrency
单核 多核
执行 T1 T2 T3 T4 T1 T2 …（时间复用） core 1：T1 T3 T1 T3…；core 2：T2 T4 T2 T4…（真正同时）
Concurrency？ ✓ ✓
Parallelism？ ✗ ✓

一句话：parallelism 一定是 concurrency，concurrency 不一定是 parallelism。

  • 多核的出现要求全新的软件设计方法，尤其重视并行编程

往年考法：正确的是「单核上通过 scheduler 的时间复用可以支持 concurrency」。错误选项把 concurrency 和 parallelism 的定义互换（「concurrency 意味着恰好同时执行」是错的），或说「多核让测试调试更容易」（更难）。

3.3 Data vs Task parallelism

做法
Data parallelism 把数据的子集分到多个核上，每个核做相同操作（分布式机器学习中常见）
Task parallelism 把线程分到多个核，每个线程做不同操作

两者不互斥，一个应用可以同时用（hybrid）。

3.4 Amdahl's Law（计算必考）

识别给一个既有串行又有并行部分的应用增加核心带来的性能增益（固定工作量下延迟的理论加速比）。S：串行比例，1−S：并行比例，N：核数。

speedup≤1S+1−SN

课件例：75% 并行、25% 串行，从 1 核到 2 核：

10.25+0.752=10.625=1.6

极限：N→∞ 时 speedup →1S（上例最多 4 倍）。

Serial portion of an application has a disproportionate effect on performance gained by adding additional cores.（串行部分对加核带来的增益影响不成比例地大）——课件图：S=0.05 时 16 核约 9 倍，S=0.10 约 6.4 倍，S=0.50 不到 2 倍。

往年考法（改写）：加速比在 1.6 到 1.7 之间的组合？逐个代入：

并行比例 核数 加速比
81% 3 1/(0.19+0.27)≈2.17
81% 5 1/(0.19+0.162)≈2.84
61% 3 1/(0.39+0.203)≈ 1.69 ✓
61% 5 1/(0.39+0.122)≈1.95

解题套路：先算 S=1− 并行比例；分母 =S+(1−S)/N；取倒数。注意题目给的是并行比例还是串行比例。

4 · 线程细节

4.1 Multithreaded process

  • 多线程进程有多个执行实例，每个有自己的 PC
  • thread 和 process 类似，但共享同一地址空间，能访问同一批数据
  • 每个线程有 PC 和私有的一组寄存器
  • 同一处理器上从 T1 切到 T2 也要 context switch：保存 T1 的寄存器状态，从 T2 的 stack（TCB）恢复 T2 的状态
    • 地址空间不变，所以 context switch 开销小得多
    • 切到另一个进程的线程，开销更大
  • 提供进程内的并行，能让 I/O 和其他活动重叠：一个线程在 CPU 上算，另一个线程在做 I/O

4.2 TCB（Thread Control Block）

thread = 唯一的执行上下文，lightweight process（PC、registers、execution flags、stack）；在处理器上执行时就驻留在寄存器里。

每个线程一个 TCB：

  • Execution state：CPU registers、PC、stack 指针
  • Scheduling info：state、priority、CPU time
  • Accounting info
  • 各种指针（实现调度队列）
  • 指向所属进程 PCB 的指针

4.3 共享 vs 私有状态

  • Thread 封装 concurrency——进程的「主动」部分
  • Address space 封装 protection——进程的「被动」部分（一个程序的地址空间和另一个不同，防止 buggy 程序搞垮整个系统）
所有线程共享 每个线程私有（在 TCB 里）
内存内容（全局变量、heap） CPU registers（含 PC）
I/O 状态（file descriptors、网络连接等） Execution stack（参数、临时变量、保存的 PC）

4.4 Thread 的生命周期

和 process 一样：new → ready → running → waiting → terminated。活跃线程由 TCB 表示，TCB 按状态组织成队列：ready queue 和各设备（tape、disk、ethernet……）的 queue，每个队列有自己的调度策略；线程不在运行时，它的 TCB 就在某个队列里。

5 · User Threads 与 Kernel Threads

User threads Kernel threads
是什么 程序中可独立执行的实体，由用户级线程库创建和管理 能在 CPU 上被调度执行，由 OS 支持和管理
kernel 知道吗 不知道（只对程序员可见）⇒ 不能被直接调度到 CPU 上 知道；OS 只管理和调度 kernel threads
例 Pthreads、Windows threads、Java threads 三大线程库（对应 POSIX、Win32、Java API） 几乎所有通用 OS：Windows、Linux、macOS、iOS、Android
  • user-level threads 提供了程序中并发和模块化的实体，OS 可以利用；程序中如果没有定义 user threads，就不会有可调度的 kernel threads
  • 所以必须建立 user threads 和 kernel threads 之间的映射

6 · Multithreading Models

模型 映射 优点 缺点 例子
Many-to-One 多个 user threads → 一个 kernel thread 一个线程阻塞（即那个 kernel thread 阻塞），所有线程都阻塞（整个进程阻塞）；不能在多核上并行（同一时刻只有一个 kernel thread 活跃） Solaris Green Threads、GNU Portable Threads（现在很少用）
One-to-One 每个 user thread → 一个 kernel thread 最大的并发；多个线程能在多处理器 / 多核上并行 创建 user thread 就必须创建 kernel thread，开销大（kernel threads 占内存、I/O 等资源）⇒ 有时要限制每个进程的线程数 Windows、Linux（现代 OS 最常用）
Many-to-Many 多个 user threads → 较少或相等数量的 kernel threads 一定程度的并发；OS 可以预先创建足够的 kernel threads——thread pool 最灵活但难实现 Windows ThreadFiber（否则不常见）
Two-level 类似 many-to-many，但允许把某个 user thread 绑定到一个 kernel thread
  • many-to-one 和 many-to-many 中「哪个 user thread 映射到 kernel thread」是一个调度问题，叫 process-contention scope（PCS）（Ch5）
  • many-to-many 的灵活性：例如在 8 核系统上一个应用可以分到比 4 核系统更多的 kernel threads
  • 随着核数越来越多，限制 kernel threads 的数量变得不那么重要 ⇒ 现在大多数 OS 用 one-to-one

7 · Threading Issues

7.1 fork() 和 exec() 的语义

  • 一个线程调用 fork()，是只复制调用线程，还是复制进程的所有线程？
  • 有的 UNIX 系统有两个版本的 fork()：
    • 如果 fork() 之后立刻 exec()，复制所有线程没必要（exec 会替换整个进程）⇒ 只复制调用线程
    • 否则复制所有线程
  • exec() 照常工作：替换整个进程，包括所有线程

7.2 Signal handling（往年选择题）

  • UNIX 用 signal 通知进程某个事件发生了；根据来源和原因，可以同步或异步接收
Synchronous signals Asynchronous signals
来源 进程自己的操作引起 运行进程外部的事件
例子 非法内存访问、除以 0 用特定按键（Ctrl+C）终止进程、timer 到期
发给谁 发给引起它的那个进程（所以叫同步）
  • 处理方式不同：有的可以忽略，有的（如非法内存访问）通过终止程序处理

Signal handler 的模式：

  1. 某个事件产生 signal
  2. signal 被递送到进程
  3. 由两种 handler 之一处理：default 或 user-defined
  • 每个 signal 都有 kernel 用的 default handler；user-defined handler 可以覆盖 default
  • 单线程进程：signal 发给该进程 / 线程
  • **多线程进程，signal 发给谁？**四种选择：
    1. 发给 signal 所针对的那个线程
    2. 发给进程中每个线程
    3. 发给进程中某些线程
    4. 指定一个线程接收该进程的所有 signal
  • 取决于 signal 的类型：
    • 同步 signal 发给引起它的那个线程，不发给其他线程
    • 某些异步 signal（如终止进程的 Ctrl+C）应发给所有线程
  • UNIX 递送 signal 的函数：kill(pid_t pid, int signal)（指定进程）
  • POSIX Pthreads：pthread_kill(pthread_t tid, int signal)（指定线程）

往年考法：关于 signal handling 错误的是「所有 signal 都应该递送给进程中所有线程」——要看类型，同步 signal 只发给引起它的线程。signal 可同步或异步接收、用户可以给某些 signal 定义 handler、同一进程中不同 signal 可以有不同 handler——都对。

7.3 Thread cancellation

  • 在线程完成前终止它；要被取消的线程叫 target thread
做法
Asynchronous cancellation 立即终止 target thread
Deferred cancellation target thread 定期检查自己是否该终止，有机会有序地结束自己
  • 发起取消只是请求取消，实际取消取决于线程的状态和类型
  • Pthreads 中，如果线程禁用了取消，取消请求会挂起直到它启用；默认类型是 deferred

为什么 asynchronous 有风险？（补充） 线程可能正在更新共享数据或持有资源，被立刻杀掉会留下不一致的数据或没释放的资源；deferred 让它在安全的检查点（cancellation point）退出。

Pthreads 代码（#include <pthread.h>）：

pthread_t tid;
/* create the thread */
pthread_create(&tid, 0, worker, NULL);   /* worker 是 start routine */
...
/* cancel the thread */
pthread_cancel(tid);
/* wait for the thread to terminate */
pthread_join(tid, NULL);

8 · OS Examples

8.1 Windows threads

  • Windows 应用作为一个独立进程运行，每个进程可有一个或多个线程；主要 API 是 Windows API
  • Windows 用 one-to-one 映射
  • 一个 Windows 线程的组成：
    • thread ID
    • register set（处理器状态）
    • PC
    • 分开的 user stack 和 kernel stack（线程在 user mode / kernel mode 运行时用）
    • 私有数据存储区（runtime 库和 DLL 用）
  • register set、stacks、私有存储区合称线程的 context

主要数据结构：

结构 在哪 内容
ETHREAD（executive thread block） kernel space 指向所属进程的指针、指向 KTHREAD 的指针
KTHREAD（kernel thread block） kernel space 调度和同步信息、kernel-mode stack、指向 TEB 的指针
TEB（thread environment block） user space thread id、user-mode stack、thread-local storage

8.2 Linux threads

  • Linux 不区分 thread 和 process：对 Linux 来说，线程只是一种特殊的进程，统称 task
  • Linux 的线程是可以和其他线程共享某些资源的进程；每个线程有自己唯一的 task_struct，看起来就是普通进程——只是碰巧和其他 task 共享资源（如地址空间）
  • 和 Windows、Solaris 形成对比：它们对线程有显式的 kernel 支持（有时称线程为 lightweight processes）

例：一个进程有两个线程：

  • Windows：一个 PCB 描述共享资源（地址空间、打开的文件），它指向两个线程；每个线程的 TCB 描述它独有的资源
  • Linux：就是两个 task，各有普通的 task_struct，被设置成共享资源

clone()：线程的创建方式和普通 task 一样，只是用 clone() 传递 flags，指定要共享的资源：

clone(CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND, 0);
flag meaning
CLONE_FS File-system information is shared
CLONE_VM The same memory space is shared
CLONE_SIGHAND Signal handlers are shared
CLONE_FILES The set of open files is shared
  • clone() 让 child task 共享 parent 的一部分执行上下文（地址空间、file descriptors、signal handler），由 flags 控制
  • 不像 fork() 那样复制所有数据结构，新 task 根据 flags 指向 parent 的数据结构
  • 普通的 fork() 可以实现为 clone(SIGCHLD, 0)（什么都不共享）

10 · 易错点

  • 同一进程的线程共享地址空间和 file descriptors；各自有 registers、PC、stack。
  • Concurrency ≠ parallelism：单核也能 concurrency，但只有多核才有 parallelism。
  • Amdahl 公式里 S 是串行比例；题目常给并行比例，要先换算。
  • Many-to-one：一个阻塞全部阻塞、不能并行；one-to-one：最大并发但开销大。
  • 现代 OS（Windows、Linux）多用 one-to-one。
  • 同步 signal（除 0、非法内存访问）只发给引起它的线程；Ctrl+C 这种才发给所有线程。
  • Pthreads 默认的 cancellation 类型是 deferred。
  • TEB 在 user space，ETHREAD / KTHREAD 在 kernel space。
  • Linux 的线程就是共享资源的 task，没有单独的线程结构。
